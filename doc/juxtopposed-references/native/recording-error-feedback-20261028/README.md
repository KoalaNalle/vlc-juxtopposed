# Recording output error callback baseline, 28 October 2026

This is a sanitized, headless LibVLC baseline and a read-only proposal. It does not establish beta readiness or a fix.

- R3 failed during setup: an executable-only option was rejected before the player was created. R4 registered the callback but did not create the intended output because the global stream-output option was overridden. Neither is a negative result for the actual writer.
- R5's deliberate missing-input positive control delivered one error callback. Its good file writer selected avformat, produced 121,979 bytes and delivered zero error callbacks. Its closed-pipe writer selected avformat, emitted a 4,096-byte prefix, logged an I/O failure, completed normally with exit code zero and delivered zero error callbacks. Both writers used a two-second stop. All eight recorded preservation guards passed and no forced cleanup was used. See `sanitized-baselines.json` for case-level results.
- This establishes a user-feedback gap for this controlled output failure. It does not identify a final-tail-only failure, test Qt or a desktop notice, prove a recording-specific failure, or provide a success/failure result to the output owner. Callback counts apply to this test with its registered callback and settings; they do not establish behavior without a provider or with interaction suppressed.

`producer-r3.py.txt`, `producer-r4.py.txt` and `producer-r5.py.txt` are byte-identical frozen test producers, included as evidence, not a recommendation to run them unchanged. Their local project paths and time deadline are historical. Each corresponding `freeze-r*.json` is the original frozen review, including the exact producer, runtime-receipt and source-header identities. `selected-runtime-identities.json` is a sanitized subset of the guarded runtime receipt, with source, fixture and selected binary identities and observed module names; the baseline's runtime guard covered the whole staged runtime, not just that subset. The original runtime receipt digest is retained, without publishing its personal profile data or raw logs.

`PROPOSAL.md` is the later, narrower read-only design, while `PRIOR-REVIEW.md` records the earlier investigation and its broader tentative proposal. Neither is an approved implementation or execution result. In particular, the proposed mux-local notification cannot distinguish all cancellation causes, cannot return conversion completion status and does not itself detect errors that the underlying AVIO path does not surface. The producer and review preimage identities do not by themselves prove a new build.

`inventory.json` distinguishes byte copies from sanitized transformations. The preimage digest list is a byte copy of a generated source-identity inventory; `sanitized-baselines.json` is a byte copy of a sanitized transformation, not a byte copy of the original run receipts. No personal profile hashes, resolved personal folders, user data, configuration files or raw logs are included. The frozen originals remain intact in ignored local build evidence.
